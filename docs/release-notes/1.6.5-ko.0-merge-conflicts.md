# 1.6.5-ko.0 병합 상충 지점

upstream `1.6.5`(`93e98bb7`)를 `release/korean`(1.5.0-ko.3)에 병합하면서 한국어 기능과 upstream 변경이 부딪힌 지점과 그 처리 결과를 정리한다. 기준은 `.claude/CLAUDE.md`의 Korean Invariants다. 한국어 전용 기능은 모두 유지하고, upstream 기능은 한국어 기능과 충돌하지 않는 한 그대로 받았다.

병합 규모: 88개 파일 충돌(내용 44, 한국어 쪽 삭제 44).

## 1. 글꼴 엔진

| 항목 | upstream 1.6.5 | 한국어 포크 | 결과 |
|---|---|---|---|
| SD 글꼴 | `.cpfont` 엔진(`SdCardFont*`, `SdCardFontSystem`), 글꼴 다운로드, 웹 `/fonts` | `.epdfont` 엔진(`UnifiedFontFamily`/`SdFontFamily`), `FontSelectionActivity` | **한국어 유지.** upstream 엔진 파일과 `FontDownloadActivity`, `TextSettingsActivity`, `TextSettingsPreview`, 웹 글꼴 페이지는 넣지 않았다. |
| TTF 글꼴 | PSRAM 보드에서 `.ttf/.otf` 직접 사용(`TtfEpdFont`, FreeType) | 없음 | **넣지 않음.** upstream SD 글꼴 레지스트리 위에 만들어져 있어 한국어 엔진과 같이 쓸 수 없다. X3/X4에는 PSRAM이 없어 원래 대상도 아니다. `FreeInkFont` 라이브러리는 `FontDecompressor`가 쓰는 `fiFontMalloc` 때문에 의존성에만 남겼고, FreeType 코드는 링크 단계에서 빠진다. |
| `EpdFontData` 구조체 | 커닝 분리 배열·희소 행렬 필드 7개 추가(#3144) | KoPub 바탕, Pretendard 헤더가 이전 필드 순서로 위치 초기화 | **헤더를 새 순서로 변환.** 새 필드는 `nullptr`로 두고 기존 packed 클래스 맵 + dense 행렬을 그대로 쓴다. 출력 결과는 같다. |
| SD 글꼴 핸들러 | `glyphMissHandler`, `coverageHandler`, `kernHandler`, `vectorBitmapHandler` | 1.5.0-ko에서 제거 | **한국어 유지(제거).** `EpdFont::hasCodepoint()` 대신 한국어 `hasGlyph()`를 쓴다. |
| UI CJK 폴백 | 문자열 단위로 SD 폴백 글꼴로 전환(`resolveTextFontId`, `prewarmFallbackText`) | 글리프 단위 폴백(`setGlyphFallback`) + 시스템 글꼴 리다이렉트 | **한국어 유지.** `prewarmFallbackText()`는 upstream 호출부를 위해 아무 일도 하지 않는 함수로 남겼다. |
| 글꼴 캐시 | `FontCacheManager`가 SD/TTF 캐시까지 관리, 스캔 버퍼를 고정 배열로 바꿈 | `UnifiedFontFamily` 맵 기준 | **upstream 구조 + 한국어 맵.** 고정 버퍼 스캔(힙 할당 없음)은 받고, SD/TTF 경로는 뺐다. `releaseSdFontCaches()`는 플래시 압축 캐시만 비운다. |
| 글꼴 맵 타입 | FreeInkUI가 `getFontMap()` 값에 바로 `.getGlyph()` 호출 | 값이 `unique_ptr<UnifiedFontFamily>` | **`UnifiedFontSlot` 추가.** `unique_ptr`을 상속하고 `getGlyph()`만 덧붙인 타입이다. SDK는 고치지 않았다. |

## 2. 렌더러

- **합성 볼드**: upstream이 글리프 그리기를 픽셀 단위 루프에서 `glyphBitmap` 래스터라이저(#3633)로 바꿨다. 한국어 합성 볼드는 픽셀마다 오른쪽 한 칸을 더 찍는 방식이었는데, 새 래스터라이저는 잉크 픽셀만 칠하므로 같은 글리프를 1px 옮겨 한 번 더 그리는 방식으로 옮겼다. 결과 픽셀은 이전과 같다. 회전 텍스트는 y를 -1 옮긴다.
- **자간 두 가지**: upstream이 `drawText(..., baseDir, int8_t tracking)`으로 글자 간격(공백이 아닌 글자 사이)을 추가했다. 한국어 `drawText(..., int8_t letterSpacing, ...)` 오버로드(TXT 양쪽 정렬에 사용, 모든 글리프 뒤에 더함)는 그대로 두고, 내부 구현에서 둘을 함께 처리한다.
- **글꼴 높이 맞춤**: upstream은 폴백 글꼴로 바뀐 문자열을 원래 글꼴의 줄 상자 가운데에 맞춘다. 한국어는 글리프 단위 폴백이라 해당 없음.

## 3. EPUB 조판

- **글자 단위 줄바꿈(`characterWrap`)**: upstream이 단어 저장을 `std::deque<std::string>`에서 `WordStore` 아레나로 바꿨다(#3518). `layoutCharacterWrap`을 새 저장 구조로 옮겼다. 알고리즘(채우기 단계, 1.0–1.5배 간격, 잉크 박스 측정, 붙은 토큰 합치기, soft flush 때 마지막 줄 토큰 보존)은 그대로다.
- **새 간격 설정의 적용**: upstream의 단어 간격(%)과 글자 간격(-2~+2px)을 글자 단위 줄바꿈 경로에도 적용했다. 단어 간격은 최소/최대 공백 폭에, 글자 간격은 토큰 폭 측정과 그리기에 들어간다.
- **링크 영역**: upstream은 줄마다 내부 링크 사각형을 페이지에 저장한다(터치 이동, 각주 강조). 한국어 줄바꿈 경로도 같은 방식으로 링크 영역을 만든다. 1.5.0-ko에서는 이 경로에 링크 정보가 없었다.
- **한글 줄바꿈 규칙**: upstream #3700은 단어 단위 줄바꿈에서 한글을 공백으로만 나누고(keep-all), 양쪽 정렬 시 음절 사이를 늘리지 않는다. 한국어 기본값(글자 단위 줄바꿈 켜짐)에는 영향이 없고, 글자 단위 줄바꿈을 끈 경우에만 upstream 규칙이 적용된다.
- **하이픈**: 하이픈은 글자 단위 줄바꿈이 꺼져 있을 때만 적용된다는 규칙을 유지했다. 사전 정의 화면(upstream 신규, EPUB 엔진으로 HTML 정의를 그림)에도 같은 규칙을 넣었다.
- **문단 들여쓰기**: upstream이 새로 만든 `ParsedText` 생성 지점 세 곳(표 셀, 중첩 블록 뒤 이어지는 텍스트)과 사전 정의 화면에서는 문단 시작이 아니므로 들여쓰기를 끄고 글자 단위 줄바꿈만 설정을 따른다.
- **줄 간격**: upstream이 "아주 넓게"(EXTRA_WIDE)를 추가했다. 한국어는 글꼴과 무관하게 1.00/1.20/1.40배를 쓰므로 같은 간격으로 1.60배를 정했다. upstream의 글꼴별 배율은 쓰지 않는다.
- **섹션 캐시 버전**: upstream 48, 한국어 42. 헤더는 upstream 48(글자/단어 간격 추가)에 한국어 `paragraphIndent`/`characterWrap`을 더한 형태이고, 버전은 **49**로 정했다. 두 계열 어느 캐시도 잘못 읽지 않는다. 모든 책이 한 번 다시 색인된다.
- **CSS 힙 보호**: upstream이 CSS 규칙 저장소를 크기 제한 구조로 다시 만들어 한국어의 `rulesBySelector_` 기반 검사가 맞지 않게 됐다. 한국어 보호(최대 연속 블록이 48KB 아래로 내려가면 규칙 추가 중단, Yes24식 자동 생성 CSS 대응)를 새 구조의 삽입 지점에 다시 넣었다. 캐시 로드 경로는 upstream의 메모리 부족 처리를 따른다.
- **하이픈 언어**: upstream이 포르투갈어를 추가했다. 한국어 빌드는 `CP_HYPHENATION_LANGS=0`으로 라틴/키릴 패턴을 빼므로, 포르투갈어도 같은 게이트(`CP_HYPHEN_LANG_PT`)에 넣었다.
- **표지 캐시**: upstream의 파일 이름(`cover_original`/`cover_legacy_v2`)을 쓰고, 한국어의 잘린 BMP 검사(크기가 헤더와 맞지 않으면 다시 생성)는 유지했다.

## 4. 설정

- **글꼴 선택**: upstream "텍스트 설정" 화면, "글꼴 관리", 글꼴 패밀리/크기 선택은 노출하지 않는다. 한국어 리더 글꼴/시스템 글꼴 선택(`FontSelectionActivity`)을 유지했다.
- **`.withTextSettings()` 항목**: upstream은 이 항목들을 텍스트 설정 화면으로 옮겨 설정 > 리더에서 숨긴다. 한국어는 텍스트 설정 화면이 없으므로 설정 > 리더와 리더 메뉴의 "읽기 옵션"에 그대로 보인다.
- **새 upstream 설정**: 단어 간격, 글자 간격, 리더 메뉴 형태, 터치 제스처, 조명, 홈 버튼, 시계/시간대, 키보드 배열, 정보 화면은 모두 받았다.
- **키보드 배열**: upstream 배열 목록이 다른 언어(`Language::FR` 등)를 참조하는데 한국어 빌드에는 영어/한국어만 있다. 영어 외 배열은 언어와 연결하지 않고 영어 이름으로 표시한다.
- **값 설정 순환 버그**: 설정 화면이 값 항목을 `int8_t`로 읽어 단어 간격 200%에서 값이 넘친다. upstream에도 있는 버그로, 여기서는 `int`로 고쳤다.

## 5. 리더

upstream 1.6이 리더를 공통 기반 클래스 `ReaderActivity`(팩토리 `create`)로 묶고 메뉴를 FUI 목록으로 바꿨다. 구조는 upstream을 따르고 한국어 기능을 그 위에 다시 붙였다.

| 항목 | 결과 |
|---|---|
| 읽기 시간 누적/초기화, 메뉴 진행 줄 표시 | 유지. EPUB은 도구 막대가 열려 있는 동안 멈춘다. |
| 자동 페이지 넘김, 그동안 자동 절전 막기 | 유지 |
| 길게 눌러 페이지 점프 | 유지. TXT에서는 upstream "챕터 건너뛰기" 설정도 한국어 추정 점프로 처리한다. |
| 읽기 옵션 하위 화면 | upstream `TEXT_SETTINGS` 메뉴 항목을 대체. 메뉴를 닫을 때 바뀐 레이아웃 설정(새 간격 설정 포함)이 있으면 한 번만 다시 조판한다. |
| 도구 막대 "글자" 패널 | upstream 글꼴 크기·포커스 읽기 행을 빼고 글꼴(한국어 선택기), 줄 간격, 정렬, 글자 간격, 단어 간격, 읽기 옵션으로 구성 |
| `cachedFontId` | 유지 |
| 뒤로 짧게 → 파일 탐색기 | upstream `ReaderUtils`가 같은 설정을 처리하므로 upstream 쪽을 쓴다. 각주 복귀가 먼저인 동작은 같다. |
| 이미지 페이지 새로고침 | upstream 새 파이프라인 사용. 한국어의 이중 FAST 새로고침은 뺐다. |
| 스파인 인덱스가 책 끝을 넘을 때 | 한국어 유지(처음으로 이동) |
| 책 열 때 "불러오는 중" 팝업 | 한국어 유지 |
| TXT 책 끝 | **upstream 채택.** 마지막 페이지에서 넘기면 홈으로 가지 않고 책 끝 화면이 나온다. 세 리더 동작이 같아졌고, 자동 넘김은 책 끝 화면에서 멈춘다. |
| TXT 페이지 계산 | **한국어 유지.** upstream은 첫 페이지 전에 전체 색인(`index.bin`)을 만들지만, 한국어는 바이트 오프셋으로 바로 연다. 페이지 번호는 계속 추정값이다. |
| TXT 메뉴 | 한국어 `TxtReaderMenuActivity` 유지. 터치 메뉴 제스처와 홈 키 리더 메뉴 동작으로도 열린다. |
| TXT 글자/단어 간격 | **적용 안 함.** upstream도 TXT에는 적용하지 않고, 한국어 TXT 줄바꿈·정렬 계산을 다시 짜야 한다. 다음 작업으로 남긴다. |
| 진행 저장(TXT) | upstream 원자적 쓰기(`ProgressFile::writeAtomic`) 사용. 파일 형식은 같다. |

## 6. 홈·절전·네트워크

- **표지 썸네일 실패**: upstream은 썸네일 생성이 실패하면 저장된 표지 경로를 지운다. 일시적 메모리 부족에도 표지를 잃으므로 한국어 동작(로그만 남김)을 유지했다.
- **절전 화면**: upstream의 새 회색조 파이프라인을 쓰고, 한국어 절전 이미지 선택(선택한 이미지가 있으면 그 중에서만 고름)과 흰 화면 방지(`setFadingFix(false)`)를 그 위에 다시 넣었다.
- **웹 서버**: upstream 경로 정규화, 이름 바꾸기, ETag/Cache-Control은 받고 글꼴 업로드/`/fonts`는 뺐다.
- **Wi-Fi, 키보드**: upstream을 따랐다. 한국어 쪽은 주석 차이뿐이었다.

- **이어서 읽기 제목**: upstream은 홈 화면 이어서 읽기 카드의 책 제목을 최대 3줄로 줄바꿈한다. 한국어는 한 줄(말줄임)로 표시한다(Lyra, 기본 테마). 세 표지 테마(Lyra3Covers)의 작은 타일 제목은 upstream대로 둔다.

## 7. OTA와 릴리스

- **설치 방식**: 한국어 유지. 펌웨어를 wolfSSL로 SD에 받은 뒤 raw write로 설치한다. upstream의 `esp_ota` 직접 스트리밍은 X4 실리콘에서 거부되고 mbedTLS로는 릴리스 CDN에 접속하지 못한다.
- **잘못된 기기 차단**: upstream(#2880, #3493)의 칩/보드 태그 검사를 다운로드 스트림에 넣었다. 맞지 않으면 다운로드를 멈추고 SD 사본을 지운다.
- **자산 이름**: 펌웨어는 upstream의 기기별 이름(`crosspoint-<tag>-x3-x4.bin`)을 찾는다. 1.5.x-ko 기기가 계속 업데이트할 수 있도록 릴리스에는 `firmware.bin`도 계속 올린다. X3/X4 외 보드는 한국어 자산을 찾지 못해 "업데이트 없음"으로 끝난다.
- **완료 안내 문구**: 한국어 유지. 한국어 설치는 기기가 스스로 재시작하므로 upstream "전원을 켜세요" 문구가 맞지 않는다.
- **빌드 대상**: upstream과 같은 matrix(x3-x4, sticky, x4pro, x4c, papermono)로 빌드한다. 기기마다 `crosspoint-<tag>-<device>.bin`(OTA·SD 업데이트용)과 `CrossPoint-<tag>-<device>-full.bin`(전체 플래시 이미지, GitHub 자산 이름은 대소문자를 구분하지 않아 OTA 파일과 겹치지 않게 `-full`을 붙인다)을 올리고, X3/X4는 기존 `firmware.bin`, `CrossPoint-<tag>.bin`, `bootloader.bin`, `partitions.bin`도 계속 올린다. upstream의 `release: published` 트리거 대신 태그 푸시로 릴리스를 만든다(릴리스 노트 파일을 본문으로 쓰기 위해). 한국어 OTA 경로(SD 다운로드 후 raw write)는 `esp_partition` API와 칩 ID 검사만 쓰므로 S3 보드에서도 같은 방식으로 동작하며, 모든 보드가 같은 `partitions.csv`를 쓴다. S3 보드의 이미지 여유는 dev 빌드 기준 papermono 약 86 KB, x4pro 약 93 KB로 작다(라틴 하이픈 패턴 포함, upstream과 같음).
- **릴리스 워크플로**: upstream의 pioarduino 고정(플랫폼 penv 안까지), `-j1`을 받았다. 태그와 `platformio.ini` 버전이 다르면 실패하는 검사와 `firmware.bin` 크기 상한(0x640000) 검사를 추가했다.

## 8. 언어

- 한국어·영어 두 언어만 둔다(플래시 용량). upstream이 추가한 불가리아어, 페르시아어, 오랑우탄어 파일도 넣지 않았다. upstream의 빌드 언어 선택(`custom_i18n_builtin_langs`, #3618)은 `all` 그대로 두며, 결과적으로 같은 두 언어가 들어간다.
- `korean.yaml`에 upstream 신규 문자열 97개를 번역해 넣었다. 한국어 fallback은 0개다. 새 생성 스크립트가 요구하는 `_bcp47: "ko"`를 추가했다. 저장 형식(`_language_code: "KOREAN"`)은 그대로라 기존 설정의 언어가 유지된다.

## 9. 빌드 환경

- upstream이 플랫폼을 `55.03.311`로 올리면서 PlatformIO Core 6.1.19 이상이 필요하다. Homebrew PlatformIO(6.1.18)로는 빌드되지 않는다. `~/.platformio/penv/bin/pio`(6.1.19)를 쓴다.
- 플랫폼이 penv의 코어를 6.2.0으로 올리면 SCons 버전이 서로 덮어써져 `No module named 'SCons.Tool.FortranCommon'`으로 실패한다(pioarduino/platform-espressif32#529). `uv pip install --python ~/.platformio/penv/bin/python "pioarduino==6.1.19"`로 고정한다.
- `freeink-sdk` 서브모듈은 upstream 고정 커밋 `111fdcc`로 올렸다.

## 10. 테스트

- upstream `test/sd_card_font`는 넣지 않은 `.cpfont` 엔진을 시험하므로 뺐다.
- upstream 테스트 중 바뀐 생성자/API(한국어 `ParsedText`, `ChapterHtmlSlimParser`, `FontCacheManager`)를 쓰는 것은 한국어 API에 맞게 고쳤다.
